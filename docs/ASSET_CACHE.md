# 素材预缓存

预缓存把已校验的游戏素材保存到玩家浏览器。优先使用服主分发的完整 ZIP 素材包，在线功能只补齐缺失或更新的文件。导入在玩家设备上完成，素材包和解压内容不会上传游戏服务器。

完整预缓存需要 **HTTPS 或 localhost**，以及支持 Service Worker、CacheStorage、Web Crypto、Worker 和 Web Locks 的现代浏览器。普通 HTTP/IP 或不支持这些能力的浏览器仍可按原方式游玩。内网穿透是否支持预缓存取决于玩家最终访问的地址是否为 HTTPS。

## 玩家使用

大厅和房间提供「预缓存」入口；大厅按钮在导航栏左侧，以绿色背景强调。输入代号的标题页不提供此入口。准备素材时停留在大厅或房间待机页，本地完整包导入为强烈推荐方式。

1. 从服主提供的渠道下载完整 ZIP 素材包，保留 ZIP，不必自行解压。
2. 点击「导入本地素材包」，选择下载的 ZIP。浏览器逐文件解压并核对当前服务器清单的大小与 SHA-256，通过后才写入缓存。
3. 查看已缓存数量和仍需补齐数量。有缺项时可以再次导入同一包、其他适用包，或点击「在线补齐缺项」。完整、未变化的文件会复用。
4. 更新后点击「检查更新与缺项」，再导入新包或在线补齐。文件是否需要更新按内容判断，不因发布版本号变化而重下全部素材。

不完整或旧版 ZIP 中仍与当前服务器一致的素材可以复用，未匹配、已变化或校验失败的文件不会冒充有效缓存。不是当前素材清单的额外文件会跳过；带有不安全路径、重复条目或加密文件等异常结构的包会拒绝。原版游戏安装包不是本功能的素材包。

操作可以暂停；关闭弹窗会继续当前任务，关闭页面则停止任务并保留已写入的文件。再次打开后检查缓存，再选择导入或补齐即可接续。接续以**完整文件**为单位，正在处理的单个文件可能需要重新处理。

进入对局会停止批量导入、补齐和完整校验，返回大厅后手动继续。同站点另一标签页处于对局时也会阻止修改操作；同一浏览器同站点同时只允许一个页面进行导入、下载、深度校验或清理，其他页面会收到忙碌提示。普通游戏素材请求保持原来的加载方式，不会排在批量下载后面。

## 检查、存储与清理

| 操作或状态 | 含义 |
|---|---|
| 检查更新与缺项 | 读取当前服务器清单，对照浏览器实际缓存条目和已校验元数据，统计缺项；不重新读取所有素材计算哈希 |
| 完整校验 | 在本机逐文件重新读取内容、核对大小和 SHA-256；发现损坏后移除对应缓存并显示缺项，不重新下载全部文件 |
| 申请持久保存 | 向浏览器申请保护本站数据，免于因空间压力自动清理；浏览器可能拒绝，界面显示实际结果 |
| 清理素材缓存 | 删除本功能的素材缓存；不删除玩家身份、设置或本机战绩。清理后可重新导入 |
| 服务器素材存在缺项 | 服务器只能提供当前实际可用的文件；客户端不能补出服务器没有的内容，应由服主补齐后重启 |

持久保存被允许后，浏览器会保护本站数据免于因空间压力被自动清理。申请通常不会弹出提示，浏览器会直接决定是否授予；窗口显示处理中、已允许、未授予、不支持或申请失败。未授予时现有缓存仍可使用，并可在以后重试；已允许或不支持此 API 时按钮禁用。主动清理站点数据仍会删除缓存。

素材保存在浏览器配置目录中的 **CacheStorage 站点数据**，由浏览器管理，没有需要玩家手动放置文件的安装目录。素材按内容哈希复用，关闭浏览器或重启设备后通常仍可使用，不需要保持解码后的图片常驻内存。

缓存按「协议＋域名＋端口」和浏览器配置隔离。更换域名、端口、浏览器、用户配置或设备后需要重新导入；同一份 ZIP 可以重复使用。无痕模式、浏览器清理、扩展或系统存储管理也可能删除缓存，申请持久保存不等于永久保留。游戏中的「清理素材缓存」与浏览器的「清理站点数据」不同，后者还可能删除身份、设置和本机战绩。

界面的本站用量和配额来自浏览器估算，不等于设备全部可用磁盘。需要留出素材、浏览器索引和更新期间旧内容保留的空间。空间不足时保留已完成文件，释放空间后再继续；不要只根据 ZIP 压缩大小判断所需容量。

Service Worker 接管页面后，已缓存且匹配当前清单的素材直接从本机返回，音频的 `/media/` 地址与原素材地址共用缓存。未命中时仍从服务器加载，符合清单且完整的响应可按需加入缓存。网页、应用代码、游戏数据、公告及 WebSocket 通信不属于此素材缓存，预缓存不是离线游戏功能，也不消除联机通信。页面首次接管前的请求及普通浏览器缓存仍遵循现有规则。

## 服主制作与分发完整包

先安装当前版本需要的素材、字体及可选本地提取素材，并核对 `data/assets.json`、`data/local-assets.json`。召唤物补充素材位于 `public/assets/local/spine/token/`，对应清单必须随素材同步。打包工具还会跟踪 Spine 图集贴图及棋盘运行时依赖，完整包不会仅凭目录总大小判断是否完整。

在项目根目录执行：

```bash
# 只检查清单、文件与逐文件 SHA-256，不生成 ZIP
npm run assets:pack -- --dry-run

# 生成完整包
npm run assets:pack

# 可选：指定输出目录
npm run assets:pack -- --out ./runtime/asset-pack-distribution
```

默认输出为 `.cache/asset-cache-pack/Stronghold-Protocol-assets-<内容版本前12位>.zip`。工具使用 Node.js 逐文件压缩，不依赖 Bandizip；可以用常规解压工具查看生成的 ZIP。包内只有素材及 `manifest.json`，没有服务器程序、依赖、身份或私人公告。存在必需缺项、校验失败或同名成品包时拒绝生成或覆盖；安装新素材后内容版本改变，会产生新文件名。生成物和游戏素材不提交 Git。

**2026-10-09 本次完整包实际结果：**12,249 个素材文件，原始总量 **611.77 MiB**，ZIP **477.11 MiB**。包含新补入的 39 套召唤物、117 个文件，中文/日语语音、字体和当前本地补充素材。数字只描述此次实际部署素材，后续以打包结果和服务器清单为准；浏览器因内容去重或存储开销，实际占用可能与原始总量不同。

将 ZIP 提供给玩家后，由玩家下载并本地导入。可以使用服主自己的静态下载站或外部网盘分发，避免游戏服务器承担首次整包流量。本功能不自动上传网盘，不依赖网盘 API，也不要求玩家向游戏服务器上传 ZIP。更换分发渠道不影响已经导入的内容。

服务器缓存清单按当前素材计算并在进程内固定。更新素材与相关清单后应重启服务器，并在更新后的素材目录制作新包；部署重启会结束正在运行的对局，参见 [部署指南](DEPLOY.md)。下载检测到清单与磁盘不一致会失败，不会以旧哈希提供新文件。玩家重新检查后只补变化文件，已打开页面使用的旧素材版本会被保留，避免对局中途混用图集与贴图。

## 在线补齐限流

在线补齐走独立下载接口，默认预算为：

| 项目 | 默认值 |
|---|---|
| 单个 Node.js 服务进程的总预算 | **1,000,000 B/s＝8 Mbps** |
| 单客户端网络地址共享上限 | **500,000 B/s＝4 Mbps** |
| 同时处理的下载 | 全局至多 24 个，同客户端网络至多 2 个 |
| 分配方式 | 总预算内按活跃客户端公平轮转，同客户端的多个请求共用其上限 |

多人下载时动态分配固定预算；人数减少后其余客户端可使用释放的份额，但不超过各自上限。家庭、校园等共用公网 IP 的玩家会共享该网络上限。队列满时返回 429 和重试间隔，客户端等待重试；多次重试仍失败时保留进度供稍后继续。

两个不同公网 IP 同时补齐时，各自理论预算可达 500000 B/s（0.5 MB/s），合计仍受 8 Mbps 限制。若启动环境显式设置过旧值 `SP_ASSET_CACHE_CLIENT_BPS=125000`，更新代码不会覆盖该设置；需改为 `500000` 或删除覆盖项后重启。

此机制不测量云服务器实际剩余出口、不按标称峰值自动提速，也不能保证消除运营商或云链路突然降速。普通游戏 HTTP、公告和 WebSocket 不使用该补齐限流器；首次按需加载仍会消耗流量。因此完整包外部分发和本地导入优先，不建议让所有玩家用在线补齐下载空缓存的全部素材。

使用以下环境变量，单位均为**字节每秒**，不是 Mbps 或 MiB/s；设置后重启服务生效：

```powershell
# Windows PowerShell：默认全服 8 Mbps，每网络 4 Mbps
$env:SP_ASSET_CACHE_TOTAL_BPS = '1000000'
$env:SP_ASSET_CACHE_CLIENT_BPS = '500000'
npm start

# 完全关闭在线补齐；本地 ZIP 导入仍可使用
$env:SP_ASSET_CACHE_TOTAL_BPS = '0'
```

```bash
# Linux/macOS
SP_ASSET_CACHE_TOTAL_BPS=1000000 SP_ASSET_CACHE_CLIENT_BPS=500000 npm start
```

多个 Node.js 进程或多台服务器各有独立预算，不会自动共享全服令牌。采用多实例部署时，应按实例分摊预算，或在统一入口额外设置限流。

## HTTPS 与反向代理

Service Worker 文件 `/asset-cache-sw.js` 必须通过同一 HTTPS 站点提供，作用域为 `/`。不要把该文件缓存为永不更新的内容，也不要把补齐接口响应改成下载附件或跳转到其他域名。素材清单接口支持 gzip 与 ETag；文件补齐接口提供完整、未压缩的 200 响应，浏览器校验后才保存，不使用 HTTP Range 续传。

补齐响应包含 `X-Accel-Buffering: no`。反向代理应允许流式转发，避免先缓存整份响应再突发发送给玩家。普通 Nginx 直连代理可以在现有 HTTPS `server` 内单独增加：

```nginx
location = /api/asset-cache/file {
    proxy_pass http://127.0.0.1:3000;
    proxy_buffering off;
    gzip off;
    proxy_read_timeout 120s;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header CF-Connecting-IP "";
}
```

这只是补齐接口配置，不替代现有页面和 WebSocket 代理。`TRUST_PROXY=auto` 默认仅接受来自本机或私有网络代理的来源头；普通 Nginx 例子清空未使用的 Cloudflare 来源头，并覆盖玩家提供的来源信息。经过可信 CDN、多层代理或内网穿透时，应按实际链路配置真实 IP，不把未校验的任意请求头当成玩家地址。代理不传真实来源时，多个玩家可能被识别为同一个客户端网络并共享限速。已有 HTTPS 与联机配置参见 [部署指南](DEPLOY.md)。
